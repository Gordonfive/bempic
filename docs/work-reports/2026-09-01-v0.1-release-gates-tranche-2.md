## Normative decisions

1. Codec ID `0` and `0xffffffff` are reserved; `1..65535` require a standards
   action; `65536..2147483647` are reviewed experimental allocations;
   `2147483648..4294967294` are shared private use and cannot support a public
   interoperability or release claim.
2. An experimental ID is never silently promoted to approved. Approval assigns
   a standards-action ID and states whether its profile is byte-identical to a
   named experimental revision. Released meanings are never reassigned.
3. `approved` and `mandatory` are distinct. Mandatory status requires two
   independently maintained interoperable implementations, compactness and
   operational evidence, migration/downgrade analysis, and an accepted
   normative decision.
4. A maximum-size claim includes every codec-owned tag, length, presence bit,
   count, padding, parameter, transform, and compression expansion. Carrier and
   security domains remain separately and truthfully accounted.
5. Worst-case evidence includes formulas/derivations, assumptions, a reaching
   semantic witness, byte/hash/length data, boundary/property evidence, and
   independent reproduction.
6. V01–V15 are stable catalog IDs. The machine catalog makes already decided
   case axes explicit while retaining `blocked_by` fields where codec or M4P
   evidence cannot yet exist.
7. First-body metrics count both directions from the first in-scope BEMPIC
   capability octet through the first selected body payload octet or through
   its committed receipt. No threshold was invented for first-body or
   resume-control cost; raw observations are mandatory.
8. M4P confirmation must come affirmatively from an identified upstream M4P
   reviewer or maintainer against immutable contract revisions. Silence or a
   BEMPIC-only assertion is insufficient.
9. The release record remains `not-ready` with `tag: null` until every roadmap
   gate and conformance requirement has immutable passing evidence.

## Architecture and repository-boundary decisions

The architecture remains exactly:

```text
OceanMail → BEMPIC → M4P → DataLink adapters
```

BEMPIC continues to own extreme-efficiency, interruption-tolerant application
synchronization, deterministic representations, durable progress, exact
integrity, receipts, and BEMPIC-byte budgets. M4P continues to own addressing,
routing, mesh coordination, forwarding, store-carry-forward, generic
fragmentation/reassembly, network deduplication, TTL, cross-modality behavior,
and the DataLink abstraction. The M4P evidence document confirms this boundary;
it does not invent missing M4P semantics.

Public specification, governance, conformance requirements, vector definitions,
and rationale remain in this repository. Executable reference implementation,
vector runners, codec implementation, simulator, fuzzing, and measured release
evidence remain owned by `bempic-reference`. The Python prototype was neither
moved nor changed and remains transitional pending sibling parity.
