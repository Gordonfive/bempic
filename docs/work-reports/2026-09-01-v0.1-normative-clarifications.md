## Normative changes and affected requirement IDs

### `semantic_bytes`

- `REQ-ACCOUNT-001` now points to the exact logical-workload definition.
- New `REQ-ACCOUNT-003` defines codec-independent recursive scalar byte rules,
  count-once selection semantics, directions, aggregation, and all exclusions.
- `REQ-METRIC-001` requires semantic fixture identity and selections in every
  result.
- New `REQ-METRIC-010` requires per-representation fixture records, the
  directional identity, independent recomputation, and aggregation isolation.
- `REQ-METRIC-003` makes restart/contact/duplicate multiplicity irrelevant to
  aggregated semantic workload.
- `REQ-VEC-001` adds content-addressed semantic fixture inputs and expected
  directional totals to every applicable bundle.
- The conformance checklist and matrix now require independent semantic counter
  reproduction.

The definition counts decoded scalar values selected by the application once
per `(direction, representation_id)` and scope. It counts normalized metadata
only when it is part of a selected decoded manifest. It excludes encoded
payload form, deferred payload, duplicates, retransmission, overlap, codec
padding, BEMPIC framing/metadata, carrier/M4P/DataLink bytes, FEC, and
lower-layer retransmission.

### Interruption, restart, and storage coverage

- `REQ-CONF-002` now defines the exact percentage formula, minimum fixture
  length, final-byte point, post-verification point, post-commit point, restart
  meanings, and memory/representation-file/durable-store logical surfaces.
- New `REQ-CONF-003` requires the exact 24-row fixed pairwise covering array,
  exact pass/fail evidence, and separate V14 before/after durable-boundary
  injection. Independent axis-only coverage is insufficient; the 72-row full
  Cartesian product is not mandatory.
- New `REQ-VEC-006` pins all V08 row IDs, fields, criteria, and pair-coverage
  proof.
- V14 machine-readable metadata pins both fault sides and both persistent
  storage surfaces.

The 24 rows cover every interruption-point/restart pair, every
interruption-point/storage pair, and every restart/storage pair. The eight
points are 0%, 1%, 10%, 50%, 90%, final-byte durable/pre-verification,
post-verification/pre-commit, and post-commit/pre-receipt. Restart parties are
sender, receiver, and both. Storage surfaces are volatile memory state,
representation file/content promotion, and the durable protocol-state store.

## Architecture and repository-boundary decisions

- The clarification changes conformance measurement and evidence, not encoded
  protocol values. No fingerprinted semantic schema changes.
- Memory, representation-file, and durable-store are logical recovery surfaces;
  an implementation may map them onto fewer physical backends but must expose
  the distinct barriers and observations.
- The fixed pairwise array is sufficient because it exhausts every two-axis
  interaction while V14 independently exhausts both sides of every named
  durable transition. This is not an acceptance-gate reduction.
- The codec registry remains empty. No codec/extension/security allocation or
  permanent wire selection is made.
- OceanMail retains object-ID/application semantics. M4P retains network-layer
  semantics, and no external M4P approval is claimed.
