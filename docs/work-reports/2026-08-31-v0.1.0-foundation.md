## Architecture and boundary decisions

1. The required stack is OceanMail → BEMPIC → M4P → DataLink adapters.
2. BEMPIC owns bounded application models, deterministic preparation,
   synchronization, persistent cross-contact progress, exact integrity,
   semantic receipts, and BEMPIC-byte budgets/accounting.
3. M4P owns addressing, routing, mesh coordination, forwarding,
   store-carry-forward, generic fragmentation/reassembly, network deduplication,
   network TTL, cross-modality behavior, and DataLink abstraction.
4. DataLink adapters/modems own framing, FEC, ARQ, retransmission, modulation,
   RF turnaround, and hardware control.
5. This repository owns public specification/governance/conformance/vector
   definitions/rationale. `bempic-reference` owns executable reference work.
6. v0.1 fixes semantic behavior and codec obligations but does not freeze a
   permanent wire codec.
7. DCCL contributes prior-art concepts only: declarative bounds and precision,
   mandatory maximum encoded size, schema fingerprints, pluggable codecs, and
   exact size analysis. No DCCL bytes, dependency, encryption, C++, or Protobuf
   requirement is adopted.
8. RFC 8785 is a specification-fingerprinting rule and the validation package
   is repository tooling only. It is not a BEMPIC carrier dependency, codec,
   wire-format choice, or executable-reference implementation.
9. The selection correction makes already-normative request semantics part of
   the schema fingerprint; it does not freeze a field layout or wire encoding.
